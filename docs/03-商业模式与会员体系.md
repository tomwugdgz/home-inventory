## 一、商业模式画布：双引擎闭环

### 1.1 画布九宫格（精简版）

| 模块 | 内容 |
|------|------|
| **客户细分** | 主用户 Tom（家庭物品管理者，愿折腾登记）；家庭成员（只查不录）；潜在同好（收纳/整理爱好者、搬家人群） |
| **价值主张** | ① 3 秒登记、一碰即查；② AI 拍照自动填字段，少打字；③ 实体贴纸让"物理世界 ↔ 数字清单"一一对应，家庭收纳可视化 |
| **渠道通路** | App（管理者高频录入 + NFC/AI 系统能力）；微信小程序（家人扫码查 + 贴纸电商入口）；内容平台（小红书/抖音收纳垂类）种草贴纸 |
| **客户关系** | 免费额度体验 → AI 提效感知 → 会员转化；贴纸耗材持续复购形成物理触点 |
| **收入来源** | **引擎一**：NFC 贴纸耗材销售（实物，一次性/复购）；**引擎二**：AI 会员订阅（视觉 Token 配额，月/季/年） |
| **核心资源** | Homebox 数据模型（位置树/标签/照片）、companion AI 识别能力、贴纸供应链、UID→物品云端映射库 |
| **关键活动** | 贴纸选品与履约、UID 绑定服务、AI 识别模型路由、内容种草 |
| **关键伙伴** | NFC 标签厂（NTAG213/215）、快递代发、视觉模型 API 供应商、支付服务商 |
| **成本结构** | 贴纸采购+物流（变动）、视觉 Token（变动，极低）、服务器+证书（固定）、获客内容（可控） |

### 1.2 两条闭环（这是整个商业模式的心脏）

```
【闭环一：硬件复购飞轮】—— 靠实体锚点锁客
  买贴纸（低价入口）
      ↓
  碰一碰 / 扫码读取 UID → 云端绑定到"这个箱子=药品"
      ↓
  用 App 管理（一碰开箱、拍照登记、颜色归类）
      ↓
  家庭扩容：新增收纳箱 / 搬新家 / 成员加入 / 颜色分类体系细化
      ↓
  再买贴纸（复购）  ←——————————— 回到起点，循环

【闭环二：会员升级飞轮】—— 靠 AI 提效转化
  免费用户体验手动录入（每月 10 次免费 AI 试用）
      ↓
  登记量上来 / 打字累 / 相似物品分不清 → 感到"录入好烦"
      ↓
  想要 AI 拍照提效（体验过免费额度，知道价值）
      ↓
  免费额度用尽 → 升级 AI 会员（月/季/年）
      ↓
  享受提效 → 登记更多物品 → 更依赖颜色/用途筛选找东西 → 续费

两环交点：会员用户登记量更大 → 需要更多贴纸 → 反哺闭环一；
         贴纸用户物理触点更多 → 打开 App 更频繁 → 更容易感知 AI 价值 → 反哺闭环二。
```

**飞轮成立的前提**：贴纸必须"跨 iPhone/安卓通用"（见 3.3 节，否则 iPhone 用户买了也不能写，飞轮从第一环就断）；AI 会员必须"先用后付费"（先给免费额度让用户感知提效，再收费，符合 `growth-retention.md` 4.4「先跑通单次付费价值，再设计订阅」）。

## 二、NFC 贴耗材的粘性逻辑：为什么实体贴能锁住用户

### 2.1 四条锁客机制

1. **沉没成本**：用户一旦为 20 个收纳箱贴好标签、把 200 件物品绑定到 UID，迁移到竞品意味着重贴 + 重录，切换成本极高。数据越多，越走不掉。
2. **物理锚点**：数字清单容易被遗忘，但贴在箱子上的实体贴纸是"看得见的提醒"——每次开箱都强化一次"我有在管理这个家"的心理认同，这是纯软件做不到的留存钩子。
3. **家庭扩容持续买**：收纳是"增量"行为——搬家、添置家具、孩子出生、换季整理都会产生新收纳单元，每一个新单元都是一次自然复购。这是打印机墨盒式的"设备→耗材"结构，但需求由生活事件自动触发，无需教育。
4. **类比验证**：打印机（低毛利机身 + 高毛利墨盒）、宜家标签/收纳体系（标准化配件生态锁定）、家庭标签机（精臣/兄弟：设备 + 标签带持续消耗）——三者共同证明"**入口低价 + 耗材复购**"在家庭场景成立。

### 2.2 贴纸 SKU 设计建议（规格、定价带、包装）

| SKU | 规格 | 定价带 | 单张成本估算 | 目标场景 |
|-----|------|--------|--------------|----------|
| 体验装 | NTAG213，10 张，纯白 | ¥19.9 | ~¥0.7/张 + 包装物流 ¥4 → 毛利率约 45% | 首次试用，低门槛 |
| 家庭装 | NTAG213，30 张，3 色分类 | ¥49 | ~¥0.7/张 + 包装物流 ¥5 → 毛利率约 47% | 主力复购款（推荐主推） |
| 大包装 | NTAG213，100 张，混色 | ¥129 | ~¥0.7/张 + 包装物流 ¥7 → 毛利率约 40% | 深度用户/搬家囤货 |
| 收藏/个性版 | NTAG215，异形/防水，10 张 | ¥29.9 | 成本略高，毛利率约 35% | 溢价 SKU，做差异化 |

> 说明：NTAG213（约 144 字节）存一个 UID + 短 URL 完全够用，是成本最优解；NTAG215（540 字节）留给需要更大容量的个性款。单张采购成本 🟡 需按实际供应链报价复核（上一轮估算 0.3~1 元/张）。

**定价策略**：主力推 30 张家庭装（¥49），把客单价拉到物流成本不敏感的区间；散装做引流不赚钱，大包装做复购锁定。**满 ¥39 包邮**是必须项——低客单被物流吃掉毛利是这类生意的头号杀手。

### 2.3 复购触发点（把"再买贴"变成系统主动提醒）

| 触发点 | 系统动作 | 转化逻辑 |
|--------|----------|----------|
| 新增收纳位置 | "检测到你新建了 1 个柜子，给它贴张标签吧" + 一键下单 | 需求刚出现，转化最高 |
| 登记物品数每破 50 件 | "你已登记 50 件，用颜色贴分类找得更快" | 从"能用"升级到"好用" |
| 检测到某位置物品 >20 件 | 建议拆分贴子标签 + 推荐家庭装 | 收纳细化的自然需求 |
| 换季/年货节/搬家季 | 内容种草 + 组合装促销 | 借生活事件节奏 |
| 贴纸颜色体系用尽 | "你有 3 类物品还没上色" | 补齐分类的心理驱动 |

## 三、iOS 不能写 NFC 的化解方案（贴纸能卖的前提，必须讲透）

这是整个硬件引擎能否成立的**一票否决点**：如果 iPhone 用户买了贴纸却写不进去，贴纸就卖不动，闭环一直接崩。上一轮 `02-方案对比表.md` 已指出"iOS 写入 NDEF 需额外权限、审核有不确定性"。本轮给出可执行化解：

### 3.1 核心思路：把"写入"从芯片搬到云端

普通认知里"给 NFC 贴写入=把数据写进芯片"，这依赖设备写卡权限（iOS 受限）。我们的方案是——**贴纸出厂即固化一个全球唯一 UID（NTAG 的 UID 出厂只读、不可改写），App 只做"读取 UID + 在云端把 UID 绑定到物品/位置"，数据存在服务器，不写进芯片**。

| 环节 | 传统"写卡"方案 | 本方案"预编码 UID + 云端绑定" |
|------|----------------|------------------------------|
| 贴纸内容 | 空白，用户设备写入 URL | 出厂固化唯一 UID（只读） |
| 用户设备需要 | 写卡权限（iOS 受限 ❌） | 只需**读 UID**（Core NFC 读 UID 不需 NDEF 写权限 ✅） |
| 绑定动作发生在 | 芯片里 | 云端数据库（UID → 物品/位置映射） |
| 跨设备通用性 | 差（写的设备才认） | **好：任何设备读出 UID → 查同一份云端绑定** |
| iPhone 支持度 | 需申请权限、审核不确定 | iPhone 7+ 读 UID 稳定支持 |

### 3.2 落地三步

1. **采购端**：向标签厂采购"预编码 UID"贴纸，UID 全局唯一且出厂固化，每批附 UID 清单。
2. **绑定端**：App 碰一碰读到 UID → 弹出"这个箱子放什么？"→ 用户选位置/物品 → 云端写入映射。iPhone/安卓走同一套 UI；二维码兜底——每张贴同时印一枚对应 UID 的二维码，无 NFC 机型扫码同样完成绑定与查询。
   > 口径澄清（对齐 04 技术方案 D6）：该"映射"以**独立的 UID 绑定表**实现（含 status 状态机 + family_id 归属 + 部分唯一索引防重复绑定），**不改动 Homebox 核心的 Item/Location 表与 API**，符合 02 报告"锁定版本、不 fork 核心、独立适配层扩展"的既定策略。采用独立表而非单字段的商业必要性：① 本方案 SKU 含"3 色分类"，用户会给同一箱子贴多张不同颜色贴（**一物多贴**）；② 换季/搬家时用户会把一张贴从旧位置改绑到新位置（**一贴换物 + 换绑历史可追溯**）——这两类真实复购/粘性场景，单字段结构无法表达。
3. **查询端**：任何人（家人用小程序扫码 / 用户碰一碰）读 UID → 云端返回绑定内容。

**结论**：贴纸成为"标准化、跨端通用的通用耗材"，不依赖任何一台设备的写卡能力——这是能规模化售卖的前提。iOS 限制从"一票否决"降为"无害约束"（只需读 UID）。

## 四、会员体系设计（免费 / 个人 / 家庭三级）

设计原则（引自 `growth-retention.md` 4.4）：权益围绕"**省时间（AI 提效）+ 身份感**"三选二，不做"省钱型"会员；先用免费额度跑通价值感知，再上订阅。

| 权益项 | 免费用户 | 个人 AI 会员 | 家庭 AI 会员（建议增设） |
|--------|----------|--------------|--------------------------|
| 手动录入物品 | ✅ 无限 | ✅ 无限 | ✅ 无限 |
| 位置树/搜索/扫码查 | ✅ | ✅ | ✅ |
| NFC 碰一碰 | ✅ | ✅ | ✅ |
| **AI 拍照识别（视觉 Token）** | **10 次/月** | **300 次/月** | **1000 次/月，多成员共享** |
| AI 抽取字段（颜色/用途/材质/类别） | 仅基础（物品名） | ✅ 全字段 | ✅ 全字段 |
| 颜色/用途筛选找物 | ✅（手动填色） | ✅（AI 自动填） | ✅（AI 自动填） |
| 家庭成员共享 AI 额度 | ❌ | ❌ | ✅（≤6 人） |
| 批量识别（一次拍多件） | ❌ | ✅ | ✅ |
| 识别失败优先队列 | ❌ | ❌ | ✅ |
| 会员身份标识 | ❌ | ✅ | ✅ |
| **价格** | ¥0 | 月 ¥12 / 季 ¥30 / 年 ¥98 | 月 ¥25 / 季 ¥68 / 年 ¥198 |

- **月付**：¥12（个人）/ ¥25（家庭）——低门槛试水。
- **季付**：¥30 / ¥68——约 ¥10~23/月，比月付省约 16%。
- **年付（主推）**：¥98 / ¥198——约 ¥8.2 / ¥16.5 每月，比月付省约 32%，锁定全年留存。
- **超额规则**：会员用完配额后**不阻断核心功能**——自动降为手动录入；另售"加购包"¥1 / 10 次。绝不让用户"付了钱还被卡住"。
- **免费额度策略**：10 次/月刻意"够体验、不够整理全屋"——一个收纳箱约 20~50 件，10 次刚好让用户尝到甜头又不够用，形成升级动机。

> 🟡 定价数字为基于价值感知的建议值，需 Tom 结合目标用户付费能力确认；`growth-retention.md` 建议"先跑通单次付费价值"，可考虑上线初期先卖"¥3 / 30 次 AI 加购包"验证付费意愿，再转订阅。

## 五、Token 成本与定价测算（诚实版）

### 5.1 单次识别成本（基于一手事实）

一手事实：**GPT-5.6 Luna 每 100 件约 $0.019（约 ¥0.14），平均延迟 3.4s**。

| 口径 | 计算 | 单价 |
|------|------|------|
| 单次识别（美元） | $0.019 ÷ 100 | **$0.00019 / 次** |
| 单次识别（人民币） | ¥0.14 ÷ 100 | **≈ ¥0.0014 / 次（0.14 分）** |
| 一次完整"拍照整理"（含识别+字段抽取+归类，按 3 次调用放大） | ¥0.0014 × 3 | **≈ ¥0.0042 / 次（0.4 分）** |

### 5.2 不同会员用量下的月度 Token 成本与毛利

按"一次拍照整理 = ¥0.0042（已含 3 倍放大）"测算：

| 用户类型 | 月拍照次数 | 月 Token 成本 | 年付会员价对应月均 | 毛利率 |
|----------|-----------|---------------|--------------------|--------|
| 免费用户 | 10（配额上限） | ¥0.042 | ¥0 | —（获客成本） |
| 轻度会员 | 30 | ¥0.13 | ¥8.2（个人年付） | ≈ 98% |
| 中度会员 | 100 | ¥0.42 | ¥8.2 | ≈ 95% |
| 重度会员（配额打满） | 300 | ¥1.26 | ¥8.2 | ≈ 85% |
| 极重度（家庭版打满） | 1000 | ¥4.20 | ¥16.5（家庭年付） | ≈ 75% |

**结论一目了然：即使重度用户把配额用满，Token 成本也只占会员费的 15~25%。** 叠加图片存储/CDN/重试等开销，真实成本会略高，但量级不变。

### 5.3 为什么用 Token 消耗做付费墙"合理"，但不夸大成本

**合理的三点理由**：
1. **可计量的天然边界**：视觉 Token 次数是一个清晰、可解释、可限制的配额单位——比"限速""限功能"更公平，用户能理解"我用一次少一次"。类比 Midjourney 的 GPU 时长。
2. **防滥用、保稳定**：无上限的 AI 调用会被少数用户刷爆，拖慢所有人；配额是服务的护栏。
3. **匹配边际成本**：虽然单价低，但确为按量产生的真实成本，配额与用量挂钩在逻辑上自洽。

**必须诚实的一点（反模式警告）**：
- **绝不能在营销里宣称"AI 成本很高，我们亏本补贴"**——家庭用量月成本不足 ¥1.5，用户一旦识破，信任反噬比不收费更糟。
- **付费墙的价值锚点是"AI 提效"，不是"成本转嫁"**：用户真正付费的理由是"省下我逐件打字、辨认用途的 20 分钟"，而不是"帮你分担几分钱算力费"。定价应对标"用户时间价值"，而非 Token 单价。
- 换个说法：Token 是**计量单位**，不是**定价依据**；定价依据是**价值**。

> 风险留口：若未来改用更贵的高精度模型、调用量激增或汇率大幅波动，单位成本可能上升——需保留"多模型路由 + 结果缓存去重 + 配额硬上限"三道保险（见风险清单 R4）。

## 六、AI 识别字段的商业价值（凭什么支撑会员定价）

Tom 点名要抽取"颜色、用途、物品"等字段。这些字段不是炫技，直接决定"找东西"的效率，是会员定价的价值来源。

| 字段 | 减少的动作 | 如何加速"找东西" | 商业价值 |
|------|-----------|-------------------|----------|
| **物品名** | 免打字、免拼写 | 搜索命中率大幅提升（"螺丝刀"不用回忆放哪格） | AI 核心卖点，免费额度即可感知 |
| **颜色** | 免手动标注 | "那个红色盒子在哪"→ 颜色筛选直达 | 视觉化找物，家庭装 3 色贴与 AI 填色联动 |
| **用途** | 免归类思考 | 按"清洁/药品/文具/工具"场景归类，一次看全 | 从"按位置找"升级到"按用途找"，是提效关键 |
| **类别** | 免选目录 | 自动归入位置树/分类体系，登记即归位 | 让"随手记"真正 3 秒完成 |
| **材质** | 免记录 | 支撑保养/保质期提醒（皮质保养、食品到期） | 为 V1.1 提醒功能埋数据基础 |

**价值闭环**：AI 自动填字段 → 登记更快（用户愿意多登）→ 数据更全（颜色/用途齐全）→ 找东西更快（筛选维度多）→ 用户感到"这钱花得值"→ 续费。这就是会员定价能站住脚的完整逻辑链：**付费买的是"找得到"，不是"识别准"**。

## 九、结论与唯一推荐（不模棱两可）

**推荐：采用"NFC 贴耗材 + AI 会员订阅"双引擎变现，主推组合如下——**

1. **硬件引擎**：主推 **30 张家庭装 ¥49**（满 ¥39 包邮），采用**预编码 UID + 云端绑定**确保跨 iPhone/安卓通用，靠"新增收纳位置"等复购触发点驱动持续购买。
2. **会员引擎**：三级体系（免费 10 次/月 / 个人 ¥98 年 / 家庭 ¥198 年），**主推年付**；AI 识别全字段为会员专属，超额降手动录入 + ¥1/10 次加购包。
3. **付费墙逻辑**：以"AI 提效（省时间）"为价值锚点，Token 仅作计量单位——**不夸大成本**（重度用户月成本 <¥1.5），毛利瓶颈不在 Token 而在付费转化与贴纸履约。
4. **分阶段落地**：先卖 ¥3/30 次 AI 加购包 + 体验装贴纸验证付费意愿（对应 `growth-retention.md`「先跑通单次付费」），跑通后再上会员订阅与家庭版。
5. **一票否决前置**：🟡 **必须先确认支付主体（个体户/公司 + 商户号）与 iOS 虚拟支付收银台方案**，否则变现无法落地。
